# 月报整理助手

## 触发条件
用户提供了本月的工作记录，需要整理成月报格式。

**数据源与存档规则（重要）**：月报/季度考核的权威数据在**腾讯文档**（季度绩效考核表 + 《工作量统计》金山文档），**不做本地存档**——直接读云端、写完交回用户。读取方法、表结构、季度考核目标写法见 `references/quarterly-performance-goals.md` 与 `references/project-index.md`。

## 输入要求
1. 上月月报模板（可选，用于参考格式）
2. 本月工作记录（零散的工作内容）

## 输出格式要求

**字数控制：600-800字（非空白字符），突出成效、讲清楚内容即可**

**格式规范：**
1. 使用纯文本格式，不使用markdown
2. 一级分类用数字+顿号：1、2、3、
3. 二级分类用数字+括号：1）2）3）
4. 同一级的多个事项用分号分隔，不换行（不使用三级列表）
5. 每个要点简洁明了，保留关键信息，突出成效
6. 项目名称加冒号后直接跟内容（如"金卡达：沟通顺利，推进签约"）
7. 优先保留：已完成的成果、关键数据、重要决策
8. 精简删除：重复表述、过程描述、次要细节

**示例格式（约650字）：**

## 月报结构框架

### 标准分类（按项目/领域）

1. **工业项目**
   1）路桥项目完善
      - 已签约项目验收（成效优先）
      - 现有智能体优化（纵向深化）
      - 新智能体应用demo（横向拓展：具体客户+进展+成效）
      - 智能体运营（bug修复、功能优化）
   2）台州市级平台升级
      - 路桥平台优化
      - 方案沟通、领导汇报结果
      - 科创立项
   3）其他地市复制
      - 丽水莲都、湖州长兴、金华永康、临海、黄岩等（简要概括每个地市进展）

2. **客经项目**
   1）企微二期验收（数据传输、模型效果、材料准备）
   2）新一期数字人项目（立项、demo）

3. **公客项目**（如有）

4. **其他事项**（团队沟通、考评、工具使用等）

## 整理规则

1. **分类归纳**：将工作按上述框架归类
   - 优先按项目归类，其次按工作性质
   - 跨项目的工作按主要归属分类
   - 分类会随业务变化调整（如从"台州项目/企微项目/科创项目"演变为"工业项目/客经项目/公客项目"）

2. **内容精简**：
   - 去掉口语化表达，合并同类事项
   - 保留关键信息：做了什么、进展如何、成效/问题
   - **重点突出成效**：如"客户认可流程和验收标准"、"方案基本认可"
   - 问题和风险也要体现：如"未达合同要求"、"效果不确定被叫停"

3. **字数控制**：
   - 目标600-800字（非空白字符）
   - 突出成效、讲清楚内容即可
   - 优先保留成果和数据，精简过程描述

4. **格式要求**：
   - 纯文本格式，不使用markdown
   - 一级用数字+顿号，二级用数字+括号
   - 同级事项用分号分隔，不换行
   - 每个要点简洁明了
   - **不使用三级列表**，用分号在同一行内展开

## 冗余的四个典型来源与修正（实战）

初稿最常出现的四类冗余，逐条对照修正：

1. **过程与结果混装** —— 一句话塞 3~4 个动作（"梳理…、推动…、组织…、完成…"），读不出到底做成了什么
   → **结果先行**：每条以"完成/通过/交付/上线/达到/投入"开头，过程动作降为定语或删除
2. **成效被埋没** —— 关键数字（准确率、金额、日期、数量）藏在长句中部，通读一遍记不住
   → **数字前置**：把 95%、81%、18 万、7.16、4 个+3 个放到句子主干位置
3. **一事多处** —— 同一工作跨线重复出现（如地市部署同时写在"应用开发"和"平台推广"里）
   → **一事一处**：按主要归属归类，其他位置只引用不回述
4. **问题混进成效** —— "考核未定""意向不强""数据不全"被当成进展写
   → **问题分离**：所有未定/受阻/风险项移入独立的「存在问题」栏

**分层结构（推荐）**：开头写 3 句「本月成效摘要」（给只看开头的领导）→ 重点工作（按业务线，结果先行）→ 存在问题（含是否需支持）→ 下月计划（可验收）。

**压缩校验**：定稿比初稿短 20%~30% 才算真精简；压缩后必须复核关键数字全部保留（准确率、金额、日期、数量、立项/验收节点）。若删减后长度没变，说明只做了结构调整、未真正去冗。

## 用户定稿格式（以此为准，2026-07 定稿）

**一级分类（不固定，别锁死）**：按当月在推进的项目／业务线命名（如某月为 工业项目／客经项目／纺织质检／其他）。**大项目会增减、改名、归并**——命名与顺序以用户当月给出的为准；若用户未给，沿用上月分类并标注“新增/归并”。
**项目索引以用户的《工作量统计》金山文档为准**（链接与用法见 `references/project-index.md`）；写月报前先用它核对当**项目线是否漏项**，不要凭印象沿用旧分类。

**分类命名用用户口径，不要改成索引官方名**：用户写“工业项目/客经项目”，而索引里叫“AI+工业项目/智能营服项目”——**定稿用用户的叫法**；索引只用来查“当月有哪些线、哪些没写到”（如“文旅中试基地”周报里可能没提，需主动问）。替用户改名 = 错。

### 跨月去重（最容易犯的错，必检）

**上月月报已报过的成果，本月不得再写一次。** 写本月前先把上月定稿过一遍，逐条对比。
已发生的真实错误：把“企微二期通过初验”和“纺织质检过产委会”又写进了 8 月——这两条 7 月月报已经报过，属于把一个成果报两次，被领导追问时很难解释。
自检：每个成效问一句“这是本月新发生的事，还是上月的存量？”；立项/初验/验收/报价这类“一次性里程碑”尤其容易跨月重复。

### 输出形态（用户定稿习惯）

用户的定稿**通常只保留「重点工作」**，不要把成效摘要/存在问题/下月计划默认塞进正文；这三段单独放“可选附加段落”文件，由用户决定是否接上。

**工业项目下的二级子项名固定为**：
1）路桥项目管理；2）智能体应用开发；3）平台升级与应用革新；4）地市复制推广；5）模型建设与问题修复
（新战线如 agentos、新方向可新增二级，但不要打乱前五项的顺序与命名）

**句式**：`N）子项名：事实1；事实2；事实3` —— 子项名加冒号后**直接跟内容**，同级事实用分号分隔**不换行**，不使用三级列表。

**用词纪律**：
- 成效数字前置（95%、81%、30%、18 万、7.16、9 个、4+3）
- **不拔高**：按用户口径写。用户会把"并投入客户使用"改为"并推进客户使用"——状态词以事实为准，不确定时用保守词
- 已签约/在谈区分清楚（"已签约"vs"沟通前向合同、预计签约"）
- 问题与成效不在同一句里混写；问题一律进入「存在问题」栏

**完整月报结构**：成效摘要（3 句，给只看开头的领导）→ 重点工作（上述格式）→ 存在问题 → 下月计划。
**字数（硬约束）**：**重点工作 ≤ 1000 字**（非空白字符）。用户会明确要求压缩，不要交 1300+ 字的初稿。

压缩顺序（从代价最小的开始）：
1. **删过程与修饰**：“正…中”“已全部”“进行了…”；“准备汇总材料与数据格式”这类可缩为“准备汇总材料及数据格式”
2. **删括号内非必要说明**：“（对方硬件、我方软件）”“（限位器+4相机）”这类可选，除非用户关心
3. **合并重复**：同一事实不得出现在两个二级子项（如温岭又写在“智能体应用开发”又写在“新方向”）
4. **删低价值事项**：行政/培训/工时类排在四类里最后被删
5. **最后才删事实**，并在回复里列出“已删哪些”，让用户能加回

**必保（无论怎么压）**：准确率/百分比（100%、88.9%、91.7%）、金额（10 万、18 万）、日期（9 月 23 日）、进度值（100%）、立项/上会/签约/投标等里程碑、牵头人名（周涛、姜嘉豪）、需向上要资源的卡点。

**自检**：定稿后用脚本数一次非空白字符，确认 < 1000；再逐项核对必保清单没丢。
