# AI 行业领域切入 · 建设思路手册（Playbook）

把"进入一个新行业做 AI 应用"这件事标准化：**从一份场景征集材料出发，七步给出可落地的建设方案**。本手册来自一次完整的「AI+工业」实战，可复用到任何新领域。

## 何时使用

- 团队要进入一个新行业/领域做 AI 应用，手头有一份「场景征集表 / 需求清单 / 申报材料 / 行业资料」。
- 需要快速回答：这行业的需求聚集在哪？哪些值得做？怎么分给团队？哪些企业能对上？能不能产品化？demo 从哪起步？
- 触发词：新行业调研、场景梳理、需求分析、demo 选题、行业切入、领域建设思路。

## 输入

一份结构化表格（xlsx/csv/在线文档），至少含：**类型 / 申报地或区域 / 场景名称 / 建设主体（企业）/ 建设内容（痛点）/ 适用行业**。若无企业列，用场景名+建设内容也行。

## 七步法

### Step 1 · 场景统计画像
- 统计：类型分布（智能体/模型/数据集等）、申报地分布、行业分布、能力域分布。
- **能力域关键词归类**（互斥取首命中，是本手册的核心可复用件）：
  `质量检测/视觉质检`、`故障诊断/预测性维护`、`工艺优化/过程控制`、`排产/调度/物流`、`机器人/具身智能`、`研发设计/仿真`、`知识问答/办公助手`、`营销/电商/市场洞察`、`供应链/采购协同`、`能源/安全/环保管控`、`数据分析/经营决策`。
- 产出：总览表 + 能力域 TOP 排行 + 图表。
- 关键词归类有噪声，接受 ~15% 未归类，不必苛求完美。

### Step 2 · 四标准筛选（筛出"值得做"的）
按四条打分，**四条全满足的是首选**：
1. 对企业效益明显（良率/能耗/交期/停机/成本）
2. 对硬件依赖少（可软交付，复用现有 PLC/DCS/MES/ERP/传感器数据，不碰产线改造）
3. 可量化评估（有硬指标）
4. 可通过训练优化（数据飞轮，越用越强）

**判断准则**：行业差异落在"知识层"（数据/知识库/参数/约束）→ 可做；落在"算法/硬件层" → 避开。避开具身机器人、智驾域控、产线集成这类硬件重的。

### Step 3 · 双框架分类看聚集
- **研产供销服**（价值链环节）：研/产/供/销/服，看需求聚集在价值链哪段。
- **人机料法环测**（制造要素）：人/机/料/法/环/测（原框架无"测"，质量检测多时补"测"）。
- 做交叉热力图，找最热的格子（如"产×法""产×机""产×测""研×法"）。
- 产出：两张分布表 + 交叉热力图 + "需求聚集在XX"结论。

### Step 4 · 行业块分工（给团队分活）
- 按"行业块"切（而非按能力切），每人深挖一个行业。
- 每块给齐四件套：**anchor 企业（可查官网）+ 主攻 demo 方向（软件优先）+ 量化指标 + 调研路径**。
- anchor 企业从表里"建设主体"列捞；表里没有的片区走网络核查。
- 调研五步：企业官网（业务痛点）→ 同类 AI/工业软件商产品（看 demo 形态）→ 公开数据集 → 行业研报/工艺常识 → 手搓 demo。
- 5~6 人建议切 6 块；5 人则把"流通侧"两块合并。

### Step 5 · 目标企业需求匹配
- 对目标片区的重点企业（网络核查：企查查/政府调研稿/新闻），套用全表同行业的"需求模板"。
- 匹配两个层面：①企业级（企业名是否在现有材料）②场景类型级（能力簇是否被覆盖）。
- 产出：三片区 × 能力 匹配总表（✅对得上 / 🟡增量 / ✗硬件重避开）。
- **常见情况**：企业是新批（对不上），但场景类型全对得上 → 可作增量用现有模板承接。

### Step 6 · 泛化与产品化判断
- 算每类能力簇的"跨行业数 + 跨企业数"作为泛化广度证据。
- 核心判断：**通用引擎（时序/CV/RAG/运筹）+ 可替换行业知识包（缺陷样本/工艺参数/知识库/设备台账/BOM约束/品类素材）**。
- 可泛化（产品化）：知识问答、故障诊断、排产调度、视觉质检、工艺优化、营销内容。
- 难泛化（避开/只做项目）：企业专用形态、具身机器人、EDA/PDK、智驾域控。
- 产品化优先级：选 1~2 个深做，用"平台+行业包"范式，数据飞轮做护城河。

### Step 7 · demo 资源地图
按场景给到"竞赛 + 数据集 + baseline"三件套，照着就能手搓 demo：
- 视觉质检：MVTec AD / WM-811K / 天池铝型材布匹 / anomalib
- 故障诊断：CWRU / Paderborn / MIMII / PHM / DCASE Task2
- RAG 问答：CRAG / CAIL / DuReader / FastGPT / RAGFlow
- 排产调度：OR-Tools / OptaPlanner / Taillard / PSPLIB
- 工艺优化：OCP / 时序 UCR / Optuna
- 化工分子：MoleculeNet / OGB / DeepChem
- 电池：NASA/Calce / PyBAMM
- 纺织设计：DeepFashion / SD+LoRA
- 营销推荐：Rossmann / CTR
- 通用口诀：PapersWithCode 找 SOTA → GitHub 拿数据集名 → HuggingFace 加载 → 改行业包装。

## 关键判断准则（贯穿全程）

1. **软件优先**：复用企业现有数据（PLC/DCS/MES/ERP/传感器），不碰产线硬件。
2. **数据飞轮**：每服务一家沉淀数据→反哺通用模型→下家更快，这是"项目转产品"的壁垒。
3. **避开硬件重**：具身机器人、智驾域控、产线集成，接项目可以，别当产品线。
4. **价值链补全**：若现有材料偏"产/研"，新需求里的"销/服/运营"是增量价值，优先吸纳。
5. **贴近实际**：demo 用真实工艺参数区间/缺陷类型/业务流程做规格（表里"建设内容"就是现成需求规格）。

## 工具栈

- **读表**：在线文档用对应 MCP（如 kdocs `sheet.get_range_data`）；本地 xlsx 用 `openpyxl`（装到隔离 venv）；大表分块拉取，结果存本地 txt 再用 Python 解析成 CSV。
- **分析**：Python + `collections.Counter`；关键词归类脚本（能力域/研产供销服/人机料法环测词典）；`score_fit.py` 式打分（价值/硬件/可量化/可训练关键词计数）。
- **可视化**：Chart.js 横向柱状图 / HTML 热力图（inline widget）。
- **企业核查**：WebSearch 搜"地区 + 重点产业 + 龙头企业"，政府调研稿/经信局稿件最实。
- **产物**：每步一份 markdown 报告 + 中间 CSV/JSON，统一存工作区。

## 避坑

- **关键词归类有噪声**：接受 ~15% 未归类，别为追求 0 未归类而过度调词典。
- **"现有材料"要先界定**：开做前确认比对目标是工作簿 / 申报书 PDF / 其他，避免返工。
- **地区归一化**：申报地写法乱（"金华市永康"/"永康"/"义乌市义乌市"），按城市关键词归并，注意市/县/区层级。
- **企业名匹配**：表里企业可能简写/全称不一，grep 命中即可，不必精确。
- **不要 6 个方向都做**：选 1~2 个产品化深做，其余作项目。
