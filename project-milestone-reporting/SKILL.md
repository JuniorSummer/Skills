# 项目里程碑 → 客户版进展周报

## When to Use / 触发条件

用户给出一张项目里程碑/进展台账（多数是金山文档、腾讯文档等在线表格链接，偶尔是 xlsx），
要求统计状态、分析风险、出周报。也适用于“读一份金山文档/Kdocs 分享链接”的取数环节（见 `references/kdocs-cli-read.md`）。
典型场景：多厂商共建项目，里程碑是甲方（客户）关注的口径，需要定期汇报。

## 工作流程

1. **取源表**
   - 金山文档 / Kdocs 链接：`kdocs-cli drive read-file url="<链接>"` —— 官方 CLI 已装并已认证，直接返回 markdown。
     匿名抓网页会被跳登录页、绕不开，别在这里耗时间。读法与凭据检查见 `references/kdocs-cli-read.md`。
   - 先 `kdocs-cli sheet get-sheets-info file_id=<id>` 确认工作表数量：`read-file` 可能只返回默认工作表，多表时逐表读。
2. **落盘**
   - `read-file` 的 stdout 重定向到文件（`> read1.json`）再解析：大文档不进对话上下文，可复查、可复用。
   - 在固定子目录里工作（如 `<项目名>周报/`），放 `read1.json`、`items.json`、生成脚本、样例、定稿。
3. **解析表格**：`python3 scripts/parse_sheet_md.py read1.json -o items.json`，再按下节核对记录数。
4. **用代码统计，不心算**：分类计数、状态计数、百分比全部由脚本输出，并打印一致性校验（各分类之和 == 总数；风险清单条数 == 正文声明的风险数）。
   数字对不上先修解析，不要改文字。
5. **判定风险（口径）**：**只收源表里明确标注的风险条目** —— 表内写有「风险点 / 重大风险点」的才算，原文照录；「组件未就绪 / 要尽快 / 等合同签署后发货 / 需排期 / 没部署」这类只是进展描述，**不算风险**。不自行分级（不分高/中/低）。匹配词用「风险点」而不是「风险」，否则会误命中产品名（如「风险态势模块」）。取句规则与写法见 `references/client-report-format.md`。
6. **先出样例 → 确认格式 → 再跑全量**（用户的明确要求，不要在未确认口径时直接出全量稿）：
   - 先挑最小的那个维度，出「整体情况 + 该维度明细 + 风险清单 + 需支持事项」，让用户看格式。
   - 确认后再全量，并在交付时**一次问清**剩余开放项（格式紧凑度、风险口径、交付方式：本地文件 / 发飞书 / 新建回在线文档），不要边做边追问。
  - 生成器写成**脚本 + 参数**（`--sample` / `--full`）：改格式只改一处重跑，不要手改报告或每轮意见重写脚本。
7. **交付**：产物写入文件，正文只给结论 + 待确认的点，并把文件路径给用户。

## 解析陷阱

- **合并单元格 / 单元格内换行会变成“首两列（分类、里程碑）为空”的续行**。这类行必须按列名并入上一条记录，
  当成新记录会让里程碑数量虚高。
- 目标列常混入会议记录或功能清单（多句、夹着客户批注）。展示时只取首个分句或首个日期节点，个别单元格做等价摘要；
  **原表数据不要改**，摘要与口径差异写进附注。
- 状态列与目标列可能自相矛盾（如状态=已完成、目标列写 “Almost Done”）。不要替用户“修好”，列进附注请其确认口径。
- 源表进展列的日期可能落后于用户口述的最新对齐版本。交付时点明数据截止日期，并提醒是否需要重读更新后的表。
- 客户批注（如「这个时间不行，太晚了」）**不是风险标记**，默认不收；要收就标明「客户批注」并原文照录，别改写成自己的判断。
- 同上，用「风险」二字匹配风险会把产品名（如「风险态势模块」）误判成风险行，收窄到「风险点」这类标记词。

## 输出规范（用户偏好，始终遵守）

- 纯文本，不用 markdown 表格；一级、二级都用「数字+顿号」（1、2、3、）。
- **一个维度一段，各维度分开概括、不合并**；每项里程碑 1–2 行：
  `序号、里程碑名【状态】｜责任方：<厂商>/<责任人>；目标：<时间>`，换行后缩进写 `进展：<一句话>`。
- 整体情况先给数字：已完成 / 进行中 / 未开始各几项及占比，再给「表内标注风险事项 X 项、需协调事项 Y 项」，然后按维度给数量与状态分布。**风险不分高/中档**（用户明确要求）。
- **客户版必须隐去手机号、邮箱**等个人信息，只留厂商名 + 责任人姓名，并在附注说明已隐去。
- 「需协调事项」**只摘表内明确写过「需协调」的语句**，原文照录；其他协同诉求（等合同签署、云资源申请中、他方排期）只是进展描述，**未被标记就不要自行抬成待办**，拿不准先问用户。
- 单列「待补充进展说明」：状态为进行中/未开始但进展列为空的条目（已完成项不算）。
- 附注写清数据口径：来源表名、进展更新截止日期、是否已与各方对齐。

## 交付前自检

- 声明的总数 / 各状态数 / 风险数 == 脚本统计值。
- 每条风险都能在原表找到「风险点」字样，没有自造判断，也没有被分成分级。
- 客户版里已无手机号、邮箱。
