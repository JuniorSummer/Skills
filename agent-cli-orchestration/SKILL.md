# 驱动外部编码 Agent CLI（编排与验收）

## When to Use

- 把一个任务交给外部 agent CLI 执行，而且**不限于写代码**：装软件、生成文档/评分表/数据、批量改写。
- 任务耗时长或多子任务，需要中途汇报，而且不能被一个子任务失败拖垮。
- 需要判断「它说的成功」是否真成功。

各 CLI 的具体 flag 见对应的 codex / claude-code / opencode 技能；本技能只管**怎么起、怎么盯、怎么验**。

## 1. 启动：长任务一律后台 + 通知

- `terminal(background=true, notify=true)` 起任务，拿 `session_id`，用 process 工具 `wait`/`poll` 看进度。
- 前台调用有超时上限（本环境约 600s），**超过上限会被自动转为后台**——结果会以通知回来，**绝对不要重跑原命令**。
- 不要"起任务后循环 sleep 占住回合"：要么等通知，要么去做不依赖它的其他工作。

## 2. 提示词里必须写明的事

1. **单个失败不要中止整个任务**。默认的"失败就停下"会让它在第一个错误后丢掉剩下 N-1 个子任务（实测一次丢掉 4/5 个）。写成："任何单个失败都记录下来继续下一个，最后逐项汇报成败"。
2. **报告体积上限**。不写上限，它会把大段命令输出粘进最终消息（见过 36KB 的报告）。写"简洁，目标 5KB 内，不要粘贴大段日志"。
3. **明确禁止危险操作**：禁止 sudo、禁止改系统设置、禁止绕过校验、禁止覆盖已有文件——否则它会为了"完成"去试你没授权的路径。
4. **给明确的文件清单**：交付分析/文档类任务时逐个列出输出文件名 + 每个文件里放什么。不列清单，它会交回一大坨需要你再拆的内容。
5. **明确禁止编造**：写清"源材料没有写的，一律标注为'未提及'，不许推测数字/日期/价格，不许引用没读过的来源"，验收时再抽样核对。
6. **产物里含中文脚本时**，要求变量一律写成带大括号的 `${var}`（不要写成 `$var` 后紧跟中文字符）：C locale 下 bash 会把后面的多字节字符并进变量名，直接报 unbound variable。

## 3. 让它真能干活的环境前提

- 需要写工作区之外：`--add-dir <dir>`（或对应 CLI 的等价参数），并说清路径。
- 需要联网：显式打开（如 `-c sandbox_workspace_write.network_access=true`）；不联网的沙箱里 curl/pip 会直接失败。
- 需要磁盘设备（挂载 dmg）、或权限总是不够时：降级到无沙箱模式（`--sandbox danger-full-access`），并把安全边界换成"明确 workdir + 干净 git 状态 + 窄任务描述 + 事后 diff 复核"。
- **用稳定路径调用**：随桌面 app 打包的 CLI（如 `ChatGPT.app/Contents/Resources/codex-cli/bin/codex`）会随 app 更新换代版本与路径，会话 PATH 也可能中途丢掉该目录。软链到 `~/.local/bin/<tool>`，并在生成的命令里用绝对路径。
- **鉴权看 CLI 自己的状态命令**（如 `codex login status`），不要用"没有 XXX_API_KEY 环境变量"推断未登录。
- 额度/限流**没有命令行读数**：只会在真跑时以 429 或用量窗口耗尽的形式出现。提前说好降级方案（换 CLI 或自己做），切换后**产出物与验收标准不变**，并在文件里注明执行体。

## 4. 验收：自报不等于完成

它最后那行 `RESULT: 成功` 是**自报**。必须自己验：

- 产物真在（路径、大小、版本号）；**"跑了很久没动静"不等于没完成**——文件往往先落盘、提交晚一步，先看目录和 `git log` 再判失败；
- 校验类结论真成立（下载包 vs 官方校验文件、解压产物 vs 已安装文件、镜像摘要）；
- 至少一次**真实调用**：能连的连一次（如用只读账号真查一次库）、能加解密的真跑一轮、能在真实文件上 lint 的就跑一次。
- 想省时间：让它把每步的「命令 / 退出码 / 关键输出」写进调查文件，你只读那个文件，**不要让它把日志贴回消息**。
- 交付物是自包含 HTML/JS 时：`node --check` 只证明语法。真跑一遍页面 JS——用 `scripts/verify_html_js.js`（jsdom + 触发 change/input + 读回计算结果）。**别假设 DOM 里两列控件的排列顺序**，先 dump 前几个控件的选项/顺序再决定怎么赋值，否则会得到"分歧=0"这类假通过。
- 判断校验工具自己的退出码时，别拿管道的 `$?`（管道最后一个命令的退出码）当它。

## 5. 并行与隔离

- 相互独立的子任务可以同时起多个 agent 进程，用独立目录/worktree 隔离，避免共享 git 索引与端口。
- 不要在同一个 terminal 调用里又起后台任务又做前台验证：依赖顺序会把握不住。

## 6. 汇报给用户

- 先说**影响决策的那一条**，再说过程：产物里如果有一个数字会改变用户的选择，那个数字排第一。
- 附件给全（文件直接发），正文只写"改了什么 / 验过什么 / 还开着什么"，不要复述过程。
